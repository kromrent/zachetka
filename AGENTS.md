# Контекст проекта «Зачётка»

Этот файл — короткая карта проекта для следующих сессий Codex. Сначала читай его, а уже затем открывай только файлы, относящиеся к задаче. Обновляй документ, если меняются архитектура, деплой, форматы данных или важные ограничения.

## Что это за приложение

«Зачётка» — личное русскоязычное PWA для подготовки к вступительному экзамену. Основное устройство пользователя — Android-телефон; приложение также запускается как Telegram Mini App.

- Production: `https://zachetka-3new.onrender.com`
- GitHub: `https://github.com/kromrent/zachetka`, ветка `main`
- Telegram-бот: `@Exam_forus_bot`
- Хостинг: Render Web Service + Render PostgreSQL
- Push в `main` автоматически запускает сборку и деплой Render.

Не помещай сюда API-ключи, пароли, токены, cookie или полные строки подключения.

## Текущий функционал

- выбор предмета и тем;
- карточки всех вопросов;
- AI-тест из 8 вариантов с одним правильным ответом;
- письменный ответ с AI-оценкой 0–25 по экзаменационным критериям;
- общие редактируемые заметки к теоретическим вопросам, доступные в письменном ответе, полном билете и лекциях;
- задачи с Java-редактором на телефоне и AI-оценкой 0–50;
- полный билет: два вопроса + задача, 60 минут, максимум 100 баллов;
- библиотека эталонных ответов;
- аудиолекции: отдельные вопросы и связные части по разделам, у каждого трека есть раскрываемый текст;
- поиск, фильтр непрослушанных, повтор, фоновое воспроизведение и Media Session;
- текстовые уточнения к конкретному вопросу лекции;
- аккаунты, Telegram-вход и синхронизация прогресса;
- установка как PWA, мобильное нижнее меню и History/Telegram BackButton.

## Банк экзамена

Главный источник полного банка — `src/question-bank.json`. Сейчас в нём 198 вопросов, 17 разделов и следующие предметы:

| id | Предмет | Разделы | Вопросы | Задачи |
|---|---|---:|---:|---:|
| `management` | Организация цифрового производства | 2 | 30 | 0 |
| `systems` | Интеллектуальные системы управления | 7 | 82 | 15 |
| `java` | Java-инженерия | 8 | 86 | 15 |

`src/data.ts` содержит типы, метаданные предметов и небольшой офлайн-набор тестов. Не принимай количество демо-вопросов в `data.ts` за размер полного банка.

Исходные PDF и распознанные материалы намеренно исключены из Git. Инструменты импорта находятся в `tools/`, но не запускай OCR или AI-пересборку банка без явной необходимости: это долго и может стоить денег.

Порядок банков, разделов, вопросов и задач является частью persistent ID. Простая перестановка элементов может привязать старые отметки, черновики, эталоны и аудиопрогресс к другим вопросам. Сохраняй порядок либо добавляй явную миграцию.

Канонический ключ теоретического вопроса для общих заметок — `${subjectId}:${sectionIndex}-${questionIndex}`. Он строится только из id предмета и индексов в `question-bank.json`; не заменяй его текстом вопроса, хешем текста, названием раздела или id аудиотрека.

## Клиентское состояние и синхронизация

Экран хранится в React, а навигация дублируется в Browser History. Выбранный предмет сохраняется в `exam-selected-subject`. Telegram BackButton должен повторять обычную кнопку «назад».

Прогресс сначала пишется в `localStorage`. Значимые ключи:

- `exam-known-{subject}` — изученные карточки;
- `exam-quiz-{subject}` и `exam-done` — тесты;
- `exam-written-draft-*` — письменные черновики;
- `exam-question-notes` — общие редактируемые заметки к теоретическим вопросам, по ключу `${subjectId}:${sectionIndex}-${questionIndex}`;
- `exam-task-progress` — код и оценки задач;
- `exam-reference-answers` — эталонные ответы;
- `exam-last-score` — последний билет;
- `exam-lecture-progress`, `exam-lecture-index`, `exam-lecture-repeat` — аудио;
- `exam-lecture-followups` — сохранённые уточнения.

`exam-code` — только старый fallback: текущая версия его читает, но не записывает.

`zachetka-question-notes-owner` не входит в progress snapshot: это локальный id владельца заметок. При смене аккаунта на одном устройстве он запрещает примешивать личные заметки предыдущего пользователя и принудительно загружает snapshot нового.

Все ключи с префиксом `exam-` отправляются в `PUT /api/progress` примерно раз в 5 секунд после входа. При первой гидратации заметки из локального и серверного snapshot сначала объединяются по question key и `updatedAt`, поэтому один snapshot не должен затирать более свежую заметку из другого. Остальная гидратация прогресса сохраняет прежнее поведение.

На сервере обычные ключи прогресса merge-ятся на верхнем уровне, уточнения к лекциям — по `id`, а `exam-question-notes` — по question key с выбором записи с более новым `updatedAt`. Пустая запись с новым `updatedAt` служит tombstone: не удаляй её из payload, иначе старая заметка может восстановиться с другого устройства. Merge прогресса выполняется в транзакции с `SELECT ... FOR UPDATE`, чтобы параллельные PUT с двух устройств не затирали друг друга. Для остальных ключей полноценного разрешения конфликтов между двумя одновременно открытыми устройствами нет.

Критический инвариант аудиопрогресса: считать объединение уникальных временных диапазонов, а не сумму `timeupdate`. Повтор одного и того же начала не должен увеличивать процент. Трек считается завершённым после 50% уникально прослушанной длительности. Не заменяй эту логику простым накопительным счётчиком.

## Аудио и стоимость

Для 198 вопросов существует 198 одиночных треков. Лекции по разделам режутся по 3 вопроса: 70 частей. Всего интерфейс потенциально показывает 268 аудиотреков.

Путь генерации:

1. `gpt-5.6-luna` (или `OPENAI_MODEL`) пишет учебный ответ и сервер сохраняет точный скрипт в PostgreSQL `lecture_text`.
2. `gpt-4o-mini-tts` (или `OPENAI_TTS_MODEL`) озвучивает именно этот сохранённый текст голосом `alloy`; если он длиннее лимита TTS, сервер режет его по границам предложений на части до 4000 символов.
3. ffmpeg склеивает части и сжимает итоговый MP3 в mono, 24 kHz, обычно 48 kbit/s.
4. Готовый MP3 сохраняется в PostgreSQL `lecture_audio` и доступен всем авторизованным пользователям.
5. Браузер дополнительно кладёт трек в Cache Storage.

`POST /api/lectures/text` использует тот же серверный cache key, что и MP3. Поэтому для новых треков показанный текст совпадает со скриптом озвучки, а параллельные запросы текста и аудио не создают два разных ответа. У старых MP3 исходные скрипты не сохранились: при первом раскрытии текста такой трек один раз расшифровывается через `OPENAI_TRANSCRIBE_MODEL`, сохраняется с `source=transcribed` и в интерфейсе помечается как автоматическая расшифровка с возможными небольшими неточностями. Текст загружается только после нажатия пользователя, поэтому старые записи не расшифровываются фоном и не расходуют баланс неожиданно.

Общий DB-кэш ограничен `LECTURE_CACHE_MAX_BYTES` (по умолчанию 800 MiB) и удаляет давно не использовавшиеся записи. Одновременные одинаковые запросы объединяются в одну задачу.

Готовый MP3 и готовый текст выдаются из БД даже без активного `OPENAI_API_KEY`; ключ нужен только для отсутствующего контента.

Есть две независимые версии кэша: seed серверного ключа в `server/index.ts` и версия браузерного cache name в `src/App.tsx`. Изменение промпта, голоса или скорости само по себе не обновит уже готовые MP3. Повышай версии только осознанно: это вызовет повторную генерацию и расходы OpenAI.

Перед массовым прогревом обязательно используй `--dry-run`, затем небольшой `--take` и `--max-new`. Не запускай несколько прогревов одновременно. HIT денег на новую генерацию не тратит; MISS тратит. Актуальную цену моделей всегда проверяй по официальному прайсу, а не по старым оценкам.

## База и авторизация

Таблицы создаются idempotent SQL при старте; отдельной системы миграций нет:

- `users` — логин или Telegram id, display name, scrypt password hash;
- `sessions` — SHA-256 hash токена, user id, срок действия;
- `progress` — один JSONB snapshot на пользователя;
- `lecture_audio` — общий BYTEA-кэш MP3 и метаданные LRU.
- `lecture_text` — общий точный скрипт или однократно восстановленная расшифровка, привязанные к ключу MP3.

Сессия живёт 30 дней в `HttpOnly`, `SameSite=Lax` cookie; в production добавляется `Secure`. Telegram `initData` проверяется HMAC и принимается не старше 24 часов. Все маршруты, способные тратить OpenAI-баланс, требуют сессию, но публичная регистрация открыта: любой посетитель может создать аккаунт и после этого расходовать API. Текущая защита — лишь общий rate limit, а не настоящий allowlist.

Если на Render отсутствует правильный `DATABASE_URL`, сервер попытается подключиться к `127.0.0.1:5432` и упадёт с `ECONNREFUSED`. Для внешнего PostgreSQL при необходимости включается `DATABASE_SSL=true`.

## API в одном месте

- auth: `POST /api/auth/register|login|telegram|logout`, `GET /api/auth/me`;
- progress: `GET/PUT /api/progress`;
- health: `GET /api/status`;
- AI: `POST /api/grade/written`, `/api/grade/code`, `/api/quiz/generate`, `/api/reference-answer`;
- lectures: `POST /api/lectures/audio`, `/api/lectures/text`, `/api/lectures/follow-up`, `GET /api/lectures/cache-status`;
- Java: `POST /api/java/compile`.

На `/api` действует rate limit 20 запросов в минуту на IP. Render — один доверенный reverse proxy (`trust proxy = 1`).

`/api/status` проверяет процесс и конфигурацию, но не делает живой запрос к БД или OpenAI.

Публичный Render сейчас намеренно не выполняет пользовательский Java-код: `ENABLE_LOCAL_JAVA=false`. AI-оценка кода работает, но реальный `javac` включай только локально. Публичное выполнение требует отдельной изолированной песочницы с лимитами и без сети.

## Переменные окружения

Шаблон находится в `.env.example`; локальный `.env` не коммитится.

- обязательные production: `DATABASE_URL`, `OPENAI_API_KEY`;
- Telegram: `TELEGRAM_BOT_TOKEN`;
- модели: `OPENAI_MODEL`, `OPENAI_TTS_MODEL`, `OPENAI_TRANSCRIBE_MODEL` (по умолчанию `gpt-4o-mini-transcribe` для старых MP3);
- аудио: `LECTURE_SPEECH_SPEED` (сейчас 1.2), `LECTURE_AUDIO_BITRATE` (48k), `LECTURE_CACHE_MAX_BYTES`;
- БД/сервер: `DATABASE_SSL`, `PORT`, `NODE_ENV`;
- только локально: `ENABLE_LOCAL_JAVA`;
- только CLI прогрева/backup: `PREWARM_USERNAME`, `PREWARM_PASSWORD`.

Никогда не выводи содержимое `.env` в логи или ответы. Если ключ был показан публично, правильное действие — отозвать его и создать новый.

## Запуск и деплой

```bash
npm install
npm run dev       # Vite + API, API на :8787
npm run build     # TypeScript + production Vite/PWA
npm run start     # Express отдаёт dist и API
```

Render настроен в Dashboard, `render.yaml` в репозитории нет. Ожидаемые команды: build `npm install; npm run build`, start `npm run start`. PostgreSQL подключается через `DATABASE_URL` в Environment. Free Web Service может засыпать и медленно отвечать на первый запрос.

Node-версия в репозитории пока не закреплена; Vite 7 требует Node `^20.19` либо `>=22.12`. `.npmrc` с `include=dev` важен: `tsx` нужен даже для production start, поэтому установка с `--omit=dev` сломает запуск. `npm run build` типизирует frontend и Vite config, но не `server/**/*.ts`; изменения backend дополнительно проверяй запуском с production-like env.

Для production-изменения: внести правку, выполнить проверки, сделать коммит, push в `main`, дождаться Render и проверить публичный URL. Старый PWA-интерфейс иногда требует полностью закрыть и снова открыть приложение из-за service worker.

## Минимальная проверка перед push

1. `npm run build`.
2. `git diff --check` и просмотр собственного diff; не затрагивать `.env` и локальные MP3.
3. На узком экране проверить выбор предмета, нижнее меню и отсутствие перекрытия контента.
4. Проверить браузерную кнопку назад и Telegram BackButton.
5. В лекциях проверить HIT-трек, play/pause, следующий, repeat, поиск, фильтр и раскрываемый текст.
6. Сохранить и изменить заметку к одному вопросу в письменном режиме, полном билете и лекциях; убедиться, что везде открылся один и тот же текст.
7. Убедиться, что повторно прослушанный диапазон не увеличивает уникальный процент.
8. После деплоя открыть `/api/status`; production-норма: `ok=true`, `ai=true`, `java=false`.

Автоматизированного полноценного test suite пока нет. Не сообщай о deploy как о готовом, пока публичная страница не отдаёт новые asset hashes и `/api/status` не отвечает.

## Известные ограничения

- Прямых URL/deep links на внутренние экраны нет; навигация хранит screen в History state.
- Режим и фильтры лекций не сохраняются, поэтому общий сохранённый индекс после смены подборки может указывать на другой трек.
- В статистике написано «из 15 задач», хотя в двух программах есть 30 вхождений; часть заданий дублируется.
- `CodeTask` сохраняет Java id как `full-{i}`, а полный экзамен — как `java-{i}`; это может давать два progress entry для одной задачи.
- Полный билет по `management` использует fallback-задачу, хотя отдельный режим кода для этого предмета отключён.
- `exam-done` увеличивается после quiz, но не после полного билета.
- `src/question-bank.json` — generated, но закоммиченный runtime source; свежий clone собирается, однако воспроизвести генерацию банка без внешних OCR-файлов нельзя.

## Рабочие правила

- Общайся с пользователем по-русски и объясняй действия простыми словами.
- Не регенерируй вопросы, эталоны или аудио без явного согласия и оценки расходов.
- Не удаляй общий DB-аудиокэш и локальные backup MP3 без отдельного подтверждения.
- Не ломай старые `localStorage` id: от них зависит сохранённый прогресс.
- Не меняй формат question key заметок `${subjectId}:${sectionIndex}-${questionIndex}` и логику tombstone/`updatedAt` без явной миграции.
- Для UI сохраняй текущую спокойную палитру и mobile-first приоритет.
- Большой `App.tsx` рефакторить постепенно; сначала сохранять поведение и форматы данных.
